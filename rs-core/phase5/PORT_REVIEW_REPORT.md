# 完整连续片段HNR会话验收（2026-10-07）

结论：**完整连续分析信号的HNR会话与帧间调度已通过桌面对照**，原小程序仍使用原JavaScript运行路径。新增代码仅在`rs-core`。

## 完成与工程保证

- 一次持有完整信号、配置和有声证据，逐个完整帧调用既有HNR算法。时间由原始样本位置计算，不采用局部时间加偏移或累加浮点帧移；最近有声证据索引持续保留，低能量帧不推进该索引。
- 每帧成功后才提交结果、游标及计数；计算失败终止会话，不能重放失败帧或将部分轨迹作为最终结果。最终均值、覆盖率和有效时长根据全部有序帧统一计算。
- 扩展完整会话的有声证据至4096行，保留旧短段接口512行、8192样本限制。默认5.25秒/63000样本/1024帧长/120帧移的517帧记录可直接计算。
- 最多两个活跃会话，句柄单调且不复用；共享结果确认规则阻止待取结果被新操作覆盖。成功结束可重复读取；未完成结束返回明确状态，取消释放所属会话而不影响另一个。
- 新增异步宿主入口，逐帧结果复制确认后调用并等待进度钩子，在帧间让出执行。取消、异步回调及调度错误均回收所属会话；WASM/数学依赖异常弃用整个实例。

## 第二模型复核

DSH进行了只读规划核对，没有写文件或执行测试。其关于失败事务、不同配置会话交错、低能量帧索引和全轨迹汇总的建议纳入实现及验证。它认为“整数帧序号乘整数帧移不等于循环累加”的说法不适用于本实现：已验证的样本范围不超过262144，乘法在整数域且不溢出，之后才转换为Float64。实现未改成浮点时间递增。其关于无声证据分支位于最近索引扫描之前的说法与代码不符，未据此改动。
